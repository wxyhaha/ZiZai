# 字在（ZiZai）全新项目开发主提示词 · v2

> 给 Codex、Claude Code 或其他具备仓库访问能力的编码 Agent 使用。本文是完整实施规范；不要求在一轮对话中完成所有阶段。

## 0. 任务身份与工作原则

你担任此项目的产品设计负责人、UI/UX 设计师、Vue 前端架构师、工程实现者和测试负责人。请严格基于随附的设计资料开发「字在」网站，产出可以运行、可以测试、可以被其他 AI 无缝接续的工程。

**这是一项全新的项目开发任务，不是对旧仓库的重构或升级。** 不要将旧仓库克隆为新项目，不要沿用旧组件、Store、路由和样式，不需要兼容旧代码、提交历史或数据结构。

工作顺序：理解需求 → 制订全程计划 → 初始化独立工程 → 构建设计系统 → 开发首页 → 开发赏字 → 实现附属功能 → 测试与修正 → 交付与记录。按阶段推进，完成并验证当前阶段后再进入下一阶段。遇到未明确的低风险细节自行做合理决策并记录；遇到版权、破坏性操作或重要产品方向变更时暂停相应动作并说明风险。

## 2. 项目名称与定位

- 中文名：**字在**。
- 英文标识：**ZiZai**。
- 副标题：中文古风字体与排版艺术。
- 主文案：**字有风骨，自在其间。**
- 产品目标：让用户在一个安静、精致的数字空间中欣赏中文字体、阅读古文，并体验不同字体与传统/现代排版方式。
- 视觉关键词：极简、书卷气、柔和纸色、真实字形、充足留白、微弱朱砂点缀。
- 反面约束：不要做成花哨国潮页、古风游戏主页、堆叠水墨插画的落地页或传统后台控制台。

**全站只有两个一级页面：首页和赏字。** 文库、字体图鉴、字体详情、版式、排版参数、题写、收藏、对照等都通过抽屉、弹层、内嵌工具、临时模式承载，不创建额外一级路由。

## 4. 技术栈与依赖原则

优先使用：

- Vue 3 + Vite + **TypeScript** + Vue Router。
- CSS Variables + SCSS：实现所有品牌外观、纸纹、布局与组件样式。
- **Reka UI**：仅在需要复杂交互时用于无样式、可访问的 Dialog、Popover、Select、Drawer/Sheet 类能力（具体组件 API 以当前官方文档为准）。
- `lucide-vue-next`：统一轻量图标（如需要）。
- Pinia：仅在多个组件有实际共享状态需求时加入；简单状态可先用 composables。
- Markdown 解析：只有明确需要时才加，用户输入的内容一律安全处理。

不要同时安装 Reka UI、shadcn-vue、Element Plus 等重复 UI 体系；不要为了落字动画使用 Three.js、WebGL 或大体积动画框架。新增依赖需要说明用途、替代方案与维护成本。

## 5. 视觉系统与页面边界

优先使用 `DESIGN_SYSTEM.md` 的色值，例如 `--paper: #F7F4EC`、`--ink: #322E2A`、`--accent: #9A5548`。页面布局以文字和留白为主体，纸纹极轻、可采用 CSS 生成；不用复杂大插画、梅竹枝叶背景、强阴影、厚重仿古边框和夸张卷轴效果。全站设计令牌集中管理，响应式规则一致。

### 5.1 首页 `/`

- **完整单屏**：占据 `100dvh` 的主场景。绝不使用向下滚动进入下一屏、滚动触发页面切换或多段式 Landing Page。
- 顶部仅保留品牌和极简导航（首页、赏字）；中央显示「字在」、主文案和「入字间」按钮；底部可有低存在感的辅助说明。
- 纸张背景轻微纹理，不影响文字对比度。背景有少量汉字自上而下缓慢飘落和横向微漂移，低透明度、合理数量、不挡 CTA，不截获指针事件。
- 动画优先 CSS transform/opacity；移动端减量、标签页不可见或减少动态偏好时合理降级；支持 `prefers-reduced-motion`。
- 在 320px 窄屏、常见手机和矮屏笔记本上主按钮仍可见；如极端矮屏不可避免，优先压缩装饰、间距与字号，而不是引入第二屏内容。

### 5.2 赏字 `/studio`

- 顶部为字体与古文选择、横排/竖排切换；中央是一张足够宽敞的可阅读书页；右侧是纤细工具栏。
- 工具栏承载字体图鉴、作品选集、版式设置、排版参数、自定义题写、对照、收藏、导出等功能。部分功能分阶段上线，但不要留下误导性的可点击空按钮。
- 长篇文章在阅读区域内部滚动，不让工具栏和页头被正文挤出视口。手机上工具栏改为底部入口，抽屉改为底部面板。
- 选中字体/文章/版式后，主阅读区域即时更新；关闭设置面板时保留当前内容与参数。
- 同一时刻只打开一个主要浮层；抽屉和对话框具备 ESC 关闭、焦点管理和键盘操作。

## 6. 功能模块与优先级

### P0：必须完成

1. 首页品牌场景、单屏布局与落字动画。
2. 赏字主体，能够显示完整真实古文。
3. 字体选择：字体目录数据化，切换后确实加载对应字体，不是仅改个标签。
4. 古文选择：题目、作者、正文一起更新；至少准备少量核对过的作品。
5. 基础横排/传统右起竖排切换。
6. 字号、行距等必要的阅读参数。
7. 自定义文字输入（纯文本，不执行 HTML）。
8. 响应式和基础无障碍操作。
9. 清晰的字体作者、来源、授权状态与使用限制记录；不明授权不能打包分发。

### P1：有价值的小功能，仍不独立成页

- 字体图鉴抽屉：字体样卡、风格标签、已验证的来源信息。
- 古文选集抽屉：按诗/词/赋/散文分类。
- 字体故事：显示设计者、说明、授权与来源链接。
- 双字体对照：同文双列，阅读区域临时切换对照模式。
- 本地收藏笺：保存字体、作品和排版参数；注意存储格式版本化与容错。
- 更多版式：册页、题签、对联等，以可插拔布局组件实现。

### P2：根据后续效果评估

- PNG 图片导出、排版样张分享、精细化字形观察、导入导出配置。
- 不急于加入登录、云同步、后端数据库、字体下载商城与 AI 生成古文。

## 7. 数据模型与渲染约束

字体、文稿、版式**必须解耦**，阅读状态将三者组合。例如：

```ts
interface FontEntry {
  id: string;
  name: string;
  family: string;
  sourceUrl?: string;
  author?: string;
  licenseName?: string;
  licenseUrl?: string;
  redistributionAllowed?: boolean | null;
  tags: string[];
  description?: string;
  files?: { src: string; format: 'woff2' | 'woff' | 'otf' }[];
}
interface TextEntry {
  id: string;
  title: string;
  author: string;
  era?: string;
  category: '诗' | '词' | '赋' | '散文' | '其他';
  paragraphs: string[];
  sourceUrl?: string;
}
type LayoutMode = 'horizontal' | 'vertical';
interface ReadingState {
  fontId: string;
  textId?: string;
  customText?: string;
  layout: LayoutMode;
  fontSize: number;
  lineHeight: number;
}
```

- 竖排使用 `writing-mode: vertical-rl`，结合 `text-orientation`，**禁止直接旋转整块内容 90 度**。
- 检查竖排标点、引号、段落缩进、数字、长文横向溢出和滚动方向；不要为单篇古文写死布局。
- 如用 Markdown 渲染外部或可编辑内容，配置安全的渲染和清理机制；用户输入优先以文本节点展示，严禁直接把它写入 `innerHTML`。
- 大字体文件按需加载，优先评估 WOFF2 与合理子集；中文缺字比文件小更严重，需要进行字符覆盖测试。
- **免费商用不等于允许再分发**。每款字体记录来源、授权条款、核对日期，未核实前使用明确的系统字体占位，并标记为「示意」，不要冒充真实字体。
- 古文原文、作者和来源要核实准确性，不将现代译注在未经授权情况下直接复制。

## 8. 分阶段开发计划与验收门槛

### 阶段 A：建立独立工程与全程计划

1. 新建干净的 Vue 3 + Vite + TypeScript 项目（建议 `zizai`）。
2. 阅读设计交付物并写出页面/组件/状态/资源规划；记录明确选择的依赖。
3. 初始化路由、主题 token、基础规范、必要的 lint / typecheck / build 命令。
4. 创建 `README.md` 与 `docs/` 交接文件。
5. 成功运行开发服务器与首次构建，记录实际命令和结果。

### 阶段 B：首页视觉与交互

1. 实现顶部极简导航、主页主视觉、纸纹、文字动效、CTA。
2. 适配桌面、平板、手机和短屏；尊重减少动态效果设置。
3. 对照首页 SVG 稿校正对齐、留白、文字比例、色彩及交互反馈。
4. 验收：没有第二屏、没有不必要花哨装饰、CTA 可用、构建成功。

### 阶段 C：赏字核心

1. 实现阅读书页、数据模型、字体加载、作品选择。
2. 实现横排/右起竖排、长文阅读和滚动行为。
3. 实现字号与行距设置、自定义题写、工具栏与基础浮层。
4. 验收：实际字体与正文可切换；横竖排长文无截断；移动端可操作。

### 阶段 D：精致功能组件

1. 字体图鉴与字体故事、古文选集分类。
2. 同文双字体对照、本地收藏和更多版式模板。
3. 统一浮层行为，避免出现弹窗套弹窗、控件堆叠和样式漂移。
4. 功能各自可独立验收，不影响 P0 核心体验。

### 阶段 E：质量保障与交付

1. 测试 320/375/390/768/1024/1440px 等典型视口和短屏高度。
2. 检查键盘、屏幕阅读器语义、ESC、焦点返回、颜色对比、减少动画模式。
3. 检查字体加载、资源路径、中文缺字、CSS 竖排、长文滚动及移动端溢出。
4. 添加适量单元测试与关键端到端测试，至少覆盖选字体、换文章、竖排、题写、关闭浮层、刷新后的持久状态（如有）。
5. 运行 typecheck、lint、test、build，修正问题；未执行的验证必须标为未验证。
6. 更新 README、设计/授权/进度文档、交接说明与遗留问题清单。

## 9. 多 AI Agent 协作与留痕（强制）

- `docs/implementation-plan.md`：阶段划分、依赖、任务状态和验收标准。

## 10. 明确禁止事项

- 不把 `fontCollections` 作为项目脚手架，也不要求兼容它。
- 不把「字体馆、文库、版式馆」重新拆回多个一级页面。
- 不把首页做成向下滚动切换多个区块或滚动进入赏字。
- 不随意引入多套大型 UI 库、复杂 3D 和多余后端。
- 不将不明来源字体当作开源素材上传，不声称未经证实的授权。
- 不将用户输入直接拼接到 HTML，也不允许无反馈的假按钮。
- 不在没有用户授权时自动删除旧仓库、修改远程仓库、推送或部署。
- 不因求快而忽略设计稿，或为“看起来有古风”擅自添加大量装饰。

## 11. 本轮启动要求（务必遵守）

**这一轮只执行阶段 A + 阶段 B：独立工程初始化、设计系统和首页。**

1. 先检查当前工作目录是否已存在新项目和未提交的用户文件，避免覆盖；无需打开旧仓库。
2. 阅读设计交付包，写出完整的阶段计划与本轮的执行清单。
3. 以干净工程实现设计系统和首页，并为赏字页建立最小可用的路由占位，使「入字间」确实可以导航。
4. 完成必要的构建和响应式检查；如无法真实执行则标明受限项。
5. 更新 `docs/progress.md` 与 `docs/handoff.md`，让下一位 AI 不需重复梳理上下文便可进入阶段 C。
6. 汇报与设计稿的差异、已验证结果、尚未完成项。除非用户另行明确要求，不要在这一轮开发赏字的全部功能或创建远程仓库。

最终目标不是「做一个带古风装饰的网站」，而是 **以真实中文字形和排版为中心、界面简约、交互精致、工程可靠且可持续扩展的「字在」**。
