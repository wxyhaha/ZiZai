### 为什么两个独立来源都要看

单个来源可能出错：仓库作者可能误标 LICENSE，字体元数据的版权字段也可能
是从上游继承下来的旧值。这里两者互相独立且一致 ——

- 仓库维护者主动选择 CC0；
- 字体制作者本人在 2021 年导出时就把版权字段写成 `Public Domain`。

两条都指向「公有领域」，因此可以放心分发。

### 本项目对该字体做过的处理

1. **裁剪**：只保留站点需要的字形（内容子集 / GB2312 完整子集两档）。
2. **格式转换**：TTF → WOFF2。
3. **未修改任何字形轮廓**，未改动字体名称，因此不涉及署名或改名义务。

## 五、字体子集的维护约束

### 字符集是怎么来的

`scripts/build-font-subsets.py` 用 glob 从源码里提取字符，而不是手写清单：

| 子集 | 字符来源 |
|---|---|
| 品牌子集 | `src/views/*.vue`、`src/components/*.vue`、`src/components/{shell,home}/*.vue`、`src/App.vue`（剥除注释、`<style>`、`<script>`） |
| 内容子集 | `src/views/*.vue`、`src/components/**/*.vue`、`src/data/*.ts`（同上剥除） |
| 完整字体 | GB2312 全部汉字（6763）+ 中文标点 + 拉丁数字 |

用 glob 而不是清单，是为了**新增组件或文案时自动纳入**，
不会因为「忘了把新文件加进来」而在页面上出现缺字。

### 必须重新生成的情形

以下任意改动后**必须**运行 `npm run fonts:build`：

- 新增或修改古文（`src/data/texts.ts`）
- 新增或修改字体条目（`src/data/fonts.ts`）
- 修改任何 `src/views/` 或 `src/components/` 里的中文文案

### 缺字的三级兜底

```
① 内容子集（随页面加载）        覆盖站内全部已收录文字
        ↓ 缺字
② 完整字体（用户点一下才下载）   覆盖 GB2312 全字，之后该字体下任意常用字都统一
        ↓ 仍缺字
③ 系统字体 / 思源宋体回退        超出 GB2312 的生僻字，界面会明确告知用户
```

第 ② 步就是「下载完整字体」策略的落地：题写面板检测到缺字才提示，
不预加载、不浪费用户流量；加载后同一字体下所有常用汉字都是同一副字形。
