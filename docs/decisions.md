## ADR-001 · 新工程从零创建，不以旧仓库为基础

**日期**：2026-11-02 ｜ **状态**：已采纳

**背景**
历史仓库 `wxyhaha/fontCollections` 只代表早期构想，其组件、Store、路由与数据结构
都不适合直接沿用；强行迁移会继承技术债。

**决策**
`npm create vite@latest zizai -- --template vue-ts` 生成干净工程，不克隆、不迁移、
不兼容旧代码。

**被否决的备选**
- 在旧仓库上改造 → 违背「全新项目」定位，且需要先审计旧代码，成本更高。
- 只参考旧仓库的《项脊轩志》文本 → 该文本本身是公有领域原文，直接采用通行版本即可，
  无需依赖旧仓库（也减少了对不可用资源的耦合）。

**影响**
工程结构完全按当前需求设计，无历史包袱。设计资料单独归档到 `docs/design-reference/`。

## ADR-002 · 依赖只装一套 UI 体系：Reka UI

**日期**：2026-11-02 ｜ **状态**：已采纳

**背景**
主提示词要求可用 Reka UI 支撑复杂交互与无障碍；同时明确禁止并存多套重复 UI 体系。

**决策**
只引入 `reka-ui`（无样式 + 可访问），视觉 100% 自绘。阶段 B 只用到了它的
`Dialog`（顶部「···」关于弹层）；阶段 C/D 的抽屉会继续复用。

**被否决的备选**
- shadcn-vue → 建立在 Reka UI 之上，会引入第二套主题与原子样式，与自有设计系统冲突。
- Element Plus / Naive UI → 默认主题是后台管理系统风格，覆盖成本极高。
- 自己从零写 Dialog 焦点陷阱 → 无障碍细节（焦点循环、Esc、`aria-modal`、
  滚动锁定、焦点返回）容易出错，不值得重写。

**影响**
阶段 B 的实际收益：`MoreMenu.vue` 只写了外观，焦点陷阱、`aria-modal`、
点外关闭、Esc 关闭、焦点返回全部由 Reka UI 保证。

## ADR-003 · 不引入 Pinia，用模块级 composable 管理共享状态

**日期**：2026-11-02 ｜ **状态**：已采纳（可在阶段 D 复审）

**背景**
目前只有两处跨组件状态：导航「···」弹层开关、阅读参数。二者都不需要
devtools 时间旅行、模块拆分或复杂派生。

**决策**
用 `src/composables/*.ts` 里的模块级 `ref` 单例 + 返回 `readonly` 包装。
`useReadingState` 统一暴露 state 与受约束的 setter（字号 14–40px、行高 1.4–3.0）。

**被否决的备选**
- Pinia → 只为两个 ref 引入状态库，增加概念与样板。
- provide/inject → 需要在根组件手动串联，反而更啰嗦。

**影响**
若阶段 D 出现「对照模式的左右栏各自持有状态」，把 `useReadingState` 从单例改成
工厂函数即可，调用方 API 不变。届时应重新评估是否引入 Pinia。

## ADR-004 · 字体采用「内容子集 + 按路由分流」，放弃 unicode-range 分片

**日期**：2026-11-02 ｜ **状态**：已采纳

**背景**
最初按 Google Fonts 的方式，把每款中文字体切成 101 个 unicode-range 分片
（浏览器按需只拉所需分片）。实测结果：

| 方案 | 首屏 CSS | 首屏字体请求 |
|---|---|---|
| 4 款字体 × 101 分片 × 1–2 字重 | **556 kB**（gzip 194 kB） | 视文本而定 |
| 内容子集方案 | **13.3 kB**（gzip 3.55 kB） | 1 个 54 kB 子集 |

556 kB 的 CSS 意味着任何页面（包括首页）都要先下载近 200 kB 才能渲染任何东西
——对一个主张「安静、克制」的站点完全不可接受，而且 600 条 `@font-face`
本身也会拖慢样式解析。

**决策**
改成两份子集，按页面分流：

1. **品牌子集**（`brand-serif.woff2`，约 107 kB）
   只含首页 / 页头 / 页脚 / 404 / 关于弹层 / 落字字池里实际渲染的 254 个字符，
   来源是设计稿的主字体**汇文明朝体**。字体族名 `ZiZai Brand Serif`，
   在 `main.ts` 里随首屏加载。
   字符集用 glob 从展示层源码提取（见 `BRAND_GLOBS`），新增文案会自动纳入。
2. **阅读子集**（四款正文字体，各 150–390 kB）
   字符集 = 站内全部古文 + 字体说明 + 界面文案（757 字），钉成静态字重。
   `@font-face` 写在 `src/styles/fonts/reading-fonts.scss`，
   只被 `ReadingView.vue` 引用 → 随赏字路由懒加载，**首页永不下载正文字体**。

构建产物验证：`dist/assets/index-*.css` 只引用 `brand-serif`；
`dist/assets/ReadingView-*.css` 引用四款正文字体。
浏览器实测：首页只请求 `brand-serif.woff2`；赏字页请求品牌子集 +
当前正文字体子集，**没有任何完整字体**被自动下载。

> 此处是原首页版本的性能记录。首页落字升级后的字体资源与加载方式见 ADR-016。

### 字重：不做合成假粗体

汇文明朝体是**单一字重**。展示层因此一律以 `font-weight: 400` 请求字形，
并在 `global.scss` 设 `font-synthesis: none`。

理由：中文的假粗体是把轮廓整体加粗，横竖笔画会糊在一起 —— 对一个以字形
为卖点的站点来说，这是最不该出现的效果。宁可标题稍轻，也不要假粗体。

### 可变字体的字重陷阱

思源宋体可变字体的**默认轴值是 200（ExtraLight）**，不是 400。
直接裁子集的话，标题会以 200 渲染，细得立不住。

处理方式：阅读子集把可变轴钉成静态 400 / 500 两个切片 —— 体积更小，
也避开不同浏览器对「可变字体 + 声明单一字重」的渲染差异。

**顺序很重要**：必须先 `sub.subset()` 再 `instantiateVariableFont()`。
反过来会让 fontTools 在 subset 阶段因重采样后的 gvar 缺少 `.notdef` 而抛错。

**代价与缓解**
- 代价：新增内容后必须重跑 `npm run fonts:build`，否则缺字。
  缓解：脚本会输出缺字报告到 `scripts/font-subset-report.json`；
  阶段 E 计划加 prebuild 校验。
- 代价：用户输入任意生僻字可能缺字。
  缓解：三级兜底 —— 内容子集 → 按需加载的完整字体（GB2312 全字）→
  系统字体/思源宋体回退。见 ADR-013。
  这条限制已写入 `docs/font-licenses.md`。

**被否决的备选**
- 坚持 unicode-range 分片 → 首屏 CSS 556 kB，不可接受。
- 只用一个巨大的全量字体 → 单文件 8–25 MB，同样不可接受。
- 走 CDN 远程加载 → 站点当前无后端，且会引入第三方可用性依赖。

## ADR-005 · 单屏首页用 `100dvh` 锁定，禁止任何滚动承载第二屏

**日期**：2026-11-02 ｜ **状态**：已采纳

**决策**
`.home` 高度 `calc(100dvh - var(--zz-header-h))`，`overflow: hidden`。
矮屏（≤700px 高）不新增内容，只压缩装饰：依次收起竖向分隔线、副标题间距、
极矮屏（≤600px）隐藏页脚入口。

**理由**
设计系统的核心约束是「首页不能使用向下滚动展示多个区块」。
用 `dvh` 而非 `vh` 是因为移动端地址栏收起时 `vh` 会造成内容被裁。

**实测**
320×568 极小屏下：无横向滚动、无纵向滚动、CTA 完整可见（410–460px）。
1440×900 下：`body.scrollHeight === 900`，精确等于视口高度。

## ADR-006 · 字体授权以「三态」建模，而不是「免费/不免费」

**日期**：2026-11-02 ｜ **状态**：已采纳

**背景**
「免费商用」不等于「允许重新分发」。设计稿的主字体「汇文明朝体」在交付包里没有授权声明。

**决策**
`FontLicenseStatus` 三态：`verified` / `use-only` / `unverified`。
- 只有 `verified` 才允许 `selfHosted: true` 并打包字体文件；
- `unverified` 的条目在界面上必须显示「示意」徽标，
  且 `font-family` 回退栈里**不含任何自托管字体的族名**（避免被误认成真字体）；
- 单元测试对此强制校验：`tests/data.spec.ts` 中断言
  「未核实授权的字体不得自托管文件」「自托管字体必须记录授权与来源」。

**影响**
「汇文明朝体」最初因授权未核实，一度以系统衬线（Songti / SimSun）近似呈现
并在界面上标注「示意」。**该字体已于同日完成核实（CC0 1.0），
现为默认正文字体**，见 ADR-014。三态机制保留 —— 将来引入新字体时，
未核实的条目依然会被挡在自托管之外，单元测试会强制校验。

**为什么保留三态而不是简化成布尔值**
布尔值表达不了「能商用但不能再分发」这一类真实存在的授权 ——
中文字体的商业授权与再分发许可常常是两套条款。三态让这种情况有位置可放。

## ADR-007 · 竖排使用 `writing-mode` + 独立标题列，不旋转容器

**日期**：2026-11-02 ｜ **状态**：已采纳

**背景**
常见错误做法是把整个文本块 `transform: rotate(90deg)`，这会破坏选中、滚动、
复制和光标行为，也无法正确处理标点。

**决策**
正文用 `writing-mode: vertical-rl; text-orientation: mixed`。
书页内部改用 `flex-direction: row-reverse`：标题作为独立的一列放在最右，
正文列在左侧横向溢出 → 与 `vertical-rl` 的阅读顺序一致，且滚动方向正确

**实现细节**
- 竖排时正文 `height: 100%`，每列正好一屏高，超出部分向左生成新列；
- 容器 `overflow-x: auto; overflow-y: hidden`；
- 段落间距用 `margin-left`（在竖排里等价于「列间距」），段首用 `text-indent: 2em`。

**实测**
1440×900 下三篇长文竖排：内容完整、无溢出、标题列与正文列不重叠。

## ADR-008 · 落字动画用 CSS keyframes + 伪随机，不用 Canvas/JS 逐帧

**日期**：2026-11-02 ｜ **状态**：已采纳

**现状更新**：CSS keyframes 与 mulberry32 继续沿用；固定 seed、旧数量和单字体字池已由 ADR-016 的每次入页随机、多字体实际覆盖字池方案取代。

**决策**
用 mulberry32 固定种子（`20261102`）生成 14/10/7/5 个落字的构型，
交给 CSS `animation` 跑 `transform` + `opacity`。

**理由**
- 固定种子 → 每次进首页构型一致，不会刷新时视觉跳跃；
- 纯 CSS 动画 → 走合成层，不占用主线程，无需 rAF 循环；
- 落字只分布在左右两侧「字道」（左 2–27%、右 73–97%），中央 40% 永远留空，
  保证不遮挡标题与 CTA；
- `prefers-reduced-motion` 时 composable 直接返回空数组 → **不渲染节点**，
  而不是渲染后隐藏（省掉图层与合成开销）。

**被否决的备选**
- Canvas / WebGL → 对「十几个字缓慢下落」是严重过度设计，主提示词也明确禁止。
- 完全随机位置（含中央）→ 会遮挡阅读与 CTA，违背设计系统 §6。

## ADR-009 · 界面字体用系统黑体，展示字体用自托管衬线子集

**日期**：2026-11-02 ｜ **状态**：已采纳

**背景**
最初把 Noto Sans SC 也自托管（9.1 MB 源文件、两字重）。但这个站点的界面文字
只有导航、按钮、标签，与系统黑体在视觉上几乎无差别，不值得为此付体积。

**决策**
- 界面字体栈 = 系统黑体（PingFang SC / Microsoft YaHei / system-ui）；
- 展示字体栈 = `ZiZai Brand Serif`（自托管子集）→ 系统宋体回退。

**影响**
删除了 `src/assets/fonts/noto-sans-sc/`，首屏字体请求只剩 1 个 54 kB 文件。
Windows 上界面文字为微软雅黑，macOS 上为苹方，观感一致且零加载成本。

## ADR-010 · 数据层与渲染层解耦：定义 `ReadingState` 渲染契约

**日期**：2026-11-02 ｜ **状态**：已采纳

**决策**
`ReadingState` 是字体 × 文稿 × 版式的组合结果，阅读组件只依赖它：
```ts
interface ReadingState {
  fontId: string
  textId: string | null
  customText: string | null   // 与 textId 互斥
  layout: 'horizontal' | 'vertical'
  fontSize: number
  lineHeight: number
  letterSpacing: number
  contentWidth: number
}
```
字体文件存于 `src/data/fonts.ts`，古文存于 `src/data/texts.ts`，两者**互不引用**；
组合发生在 `useReadingState()`。任何字体可以与任何文稿、任何版式组合。

**约束**
`customText` 永远以文本节点渲染（`{{ paragraph }}`），全项目 ESLint 开启
`vue/no-v-html: error`，禁止把用户输入拼进 HTML。

## ADR-011 · 设计令牌集中管理，组件禁止写裸色值

**日期**：2026-11-02 ｜ **状态**：已采纳

**决策**
所有颜色、字号、字距、间距、圆角、动效曲线集中在 `src/styles/tokens.scss`，
组件 SCSS 只允许引用 `var(--zz-*)`。

**理由**
站点视觉的关键是「统一、精致」；一旦允许组件内写色值，纸色系很快就会漂移出
五六种近似米色。令牌化后，换纸色只需改一处。

**例外**
书页内部的点阵纹理使用了 `rgb(138 111 82 / 5.8%)` 这类需要精确控制的三位色值，
属于纹理参数而非语义色，留在组件内并加了注释说明。

## ADR-012 · 文档与代码同等对待，未验证的功能不标「已完成」

**日期**：2026-11-02 ｜ **状态**：已采纳

**决策**
`docs/implementation-plan.md` 用四态标记（✅ / 🟡 / ⏳ / 🚫）。
凡是没有实际运行验证过的（例如屏幕阅读器实机朗读、跨浏览器竖排表现），

## ADR-013 · 自定义文字的缺字策略：按需下载完整字体

**日期**：2026-11-02 ｜ **状态**：已采纳（由用户拍板）

**背景**
内容子集只覆盖站内已收录的约 750 个字符。用户在题写面板输入自定义文字时，
可能用到子集外的字 —— 比如输入「山有木兮木有枝，心悦君兮君不知」，
其中「枝、心、悦、君」都不在站内文稿里。

**三个备选**

| 方案 | 做法 | 代价 |
|---|---|---|
| (a) 接受缺字 | 缺的字回退到系统字体 | 同一段文字里字形混杂，观感断裂 |
| (b) 按需下载完整字体 | 检测到缺字才拉一次完整字体 | 一次 1.5–4.3 MB 流量 |
| (c) 服务端按需子集化 | 服务端实时生成子集 | 需要后端，当前架构不含 |

**决策**
采用 **(b)**（用户明确选择）。落地方式：

1. 每款字体除内容子集外，另外生成一份 **GB2312 全字**版本（6763 汉字 + 标点 + 拉丁），
   文件名 `*-full.woff2`。
2. 构建脚本同时导出 `src/data/font-coverage.json`：每款字体「内容子集覆盖哪些码位」
   「完整字体覆盖哪些码位」，压成 unicode-range 字符串。
3. 题写面板用这份覆盖表做**实时缺字检测**，只有真的缺字才出现提示与加载按钮。
4. 加载用 `FontFace` API 动态注入，**与内容子集同名同字重**；
   加载完成后页面自动补全字形，阅读组件不需要改任何 CSS 变量。
5. 连完整字体也覆盖不到的字（超出 GB2312），界面会**额外说明**，不让用户以为
   点一下就能解决。

**为什么不预加载**
完整字体 1.5–4.3 MB。绝大多数用户不会输入生僻字，预加载等于白花流量。
实测：首页与赏字页在正常使用下**不会请求任何完整字体**。

**为什么用 GB2312 而不是全量 CJK**
全量 CJK 单文件 7.7–10.5 MB，是 GB2312 子集的 2–3 倍，而 GB2312 已经覆盖
日常书写的 99% 以上。真要用到 GB2312 之外的字，第三级系统回退兜着。

**实测结果**
- 4.2 MB 的汇文明朝体完整字体，本地加载耗时 263–628 ms；
- 加载后「黠」等字确认使用该字体自身字形（canvas 像素比对，与回退字体差异
  显著大于两种字体的基线差异）；
- 连完整字体也没有的「龘」会额外提示「完整字体也未收录」。

## ADR-014 · 汇文明朝体作为全站主字体（正文 + 标题）

**日期**：2026-11-02 ｜ **状态**：已采纳（由用户拍板）

**背景**
汇文明朝体是设计稿指定的主字体，但最初因**授权未核实**被降级为「示意」，
改用系统衬线近似。用户确认该字体开源后，我做了独立核实。

**核实过程与结论**

两个互相独立的来源一致指向公有领域：

1. 取材仓库 `bosswnx/huiwenmincho-improved` 的 `LICENSE` 全文为 **CC0 1.0**；
2. 字体文件内嵌 `name` 表 `nameID 0`（版权声明）内容为 **`Public Domain`**。

单个来源都可能出错（仓库可能误标，元数据可能继承自上游旧值），
两者独立且一致，因此判定可以安全分发。完整记录见 `docs/font-licenses.md`。

**决策**
- 汇文明朝体成为**默认正文字体**（替换原先的霞鹜文楷默认值）；
- 首屏品牌子集的源字体也改为汇文明朝体 —— **首页标题与正文用同一副字形**，
  全站视觉才连贯；
- 展示层字重统一为 **400**（该字体只有单一字重），并在 `global.scss` 设
  `font-synthesis: none`，杜绝浏览器合成的假粗体。

**被否决的备选**
- 只在正文用它、首页继续用思源宋体 → 首页与阅读页字形不同源，
  明朝体与宋体的差异在大字号下肉眼可见，割裂感明显。

**影响与遗留**
- 该字体缺「楯」（U+696F），《项脊轩志》「旧时栏楯」会回退到系统宋体/思源宋体。
  这是原字体本身没有该字形，完整字体策略也解决不了，已在界面与文档中说明。
- 本体是 2021 年版本。仓库 README 提到原作者后续发布了新的汇文系列，
  另有社区成员用扩散模型补了 1.6 万缺字。知乎页面返回 403 无法直接核对，
  待能验证来源与授权后可以升级。

## ADR-015 · 全量 WOFF2 保留原字体完整内容

**日期**：2026-11-02 ｜ **状态**：用户已确认要求，转换实现待调整

**背景**
当前名为 `*-full.woff2` 的资源实际是 GB2312 目标范围版本，不等于原字体全部内容；当前脚本还会把阅读用可变字体固定到 400 字重。用户明确要求完整保留原字体所有文字。

**决策**
- 全量版本必须保留原字体的全部字符映射、字形及原有排版功能；可变字体保留原有可变轴能力。
- 全量转换与内容子集生成应分开，不再用 GB2312 子集冒充原字体全量版本。
- 字符覆盖、字形、排版表和可变轴要在转换前后核对；文件生成成功不能代替完整性验收。
- WOFF2 压缩本身保持字形显示与功能；内部重排与数字签名处理意味着转换前后文件不必逐字节相同。原始 TTF/OTF 仍保留作为输入与核验基准。

**当前边界**
全量字体转换实现仍未调整，完整字符与原字体功能保留的要求继续待实现；首页有独立的随机展示子集，不代表全量字体，也不会改变全量版本的完整性要求。原字体本身缺少的字无法通过格式转换补上。

**来源**
用户在本次讨论中的明确要求；格式说明参考 https://www.w3.org/TR/WOFF2/#CompressedDataFormat 。

## ADR-016 · 首页随机落字使用实际 cmap 字池与专用字体子集

**日期**：2026-11-02 ｜ **状态**：已采纳

**背景**
原首页用少量固定汉字和单一品牌字体。若从 Unicode 范围直接随机造字，实际字体缺字时会出现无提示的系统字体替代；若为求覆盖而预载赏字页完整字体，又会增加首页资源负担。

**决策**
- `scripts/build-home-glyph-fonts.py` 从四款原始字体的 cmap 只筛选实际存在的汉字，每款以固定构建 seed 抽样 1,000 个 GB2312 一级字和 200 个长尾字，并验证生成的 WOFF2 仍包含每个抽样码位。
- 首页运行时按每次页面实例生成的随机 seed 选字、选字体；注入相同 seed 可复现。字体概率可按 fontId 配置。
- 首页字池含 4,800 个字体—字符映射，合并后 3,479 个不同汉字；运行时以 90% 概率选择 GB2312 一级常用字、10% 概率选择长尾字。PC 渲染 70 个节点，旧的平板/手机兼容档仍为 12/8 个，中心安全宽度分别为 30%/46%/50%。
- 字体资源和 CSS 独立于赏字字体与 `*-full.woff2`；`HomeView.vue` 引入生成的首页样式，按 Unicode 范围和实际使用按需加载。完整字体保留要求仍遵循 ADR-015。
- 源字体变化时运行 `npm run fonts:home`，不得手动编辑生成的字池或 `home-glyphs.scss`。

**产物与取舍**
当前构建输出中四个落字子集合计 2,066,064 字节（约 2.07 MB）：汇文明朝体 795,964 字节、霞鹜文楷 324,580 字节、朱雀仿宋 459,400 字节、思源宋体 486,120 字节；品牌字体另为 109.17 kB。首页字池保留长尾字符以维持变化，但降低其出现比例；这些子集仍不是完整字体。

**动画与无障碍**
CSS 只改变 `transform` / `opacity`，标准 PC 首页为 70 个节点；极矮视口会根据 32px 最小字号的垂直容量减少节点，避免缩小字号或产生重叠。每侧按可用侧宽分成 3 或 4 条独立字道，各道从 24/27/31/34/38/41/45/48 秒中分配不同周期；道内周期相同，采用疏密变化明显且带最小安全间距的随机相位，避免字形追越并减弱等距排列感。左右字道宽度分别抽样，字数、字形横向位置和漂移方向也随机变化，避免画面形成左右镜像节奏；漂移及旋转后的完整包围范围限制在道内，不同字道轨迹不相交。PC 字号严格限制在 32–64px，逐字随机；每列按宽度、节点数和视口高度计算安全上限，并将字号随机分配到该列可用区间的两端。左右两侧保留 30% 中央安全区域。减少动态效果时 composable 不生成节点，装饰层 `aria-hidden` 且不接收指针事件。

后续产品开发与验收以 PC Web 为目标；手机和平板现有行为作为兼容保留，不作为新增适配要求。
